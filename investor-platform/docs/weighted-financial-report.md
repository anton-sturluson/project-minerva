# Annual market-value-weighted financial report

This documents the offline pilot's manual Python library. The current Post-mortem app uses the separate [account/year financial-history API](decisions/0009-bind-reviewed-history-to-account-snapshots.md): reviewed native-currency annual/LTM measures, dated USD per-share conversion, and headline comparisons against the prior year's actual portfolio. The manual library remains available; its USD annual-profile and identical-contributor comparison rules below apply only to that library.

`build_weighted_report(snapshot, profiles)` is a pure calculation. It uses explicit calendar-year-end USD equity market values and saved outputs from `investor-financial show`. It does not read portfolio accounts, fetch prices, infer quantities or write database records. `render_weighted_report(report)` renders cited Markdown; retain the JSON beside it for exact provenance. ([Implementation](../backend/src/investor_platform/weighted_financial.py))

The snapshot contains `synthetic`, `base_currency`, `holdings_date`, `source` and `holdings`. Each holding contains a confirmed `issuer_key` and positive decimal-string `market_value`; a ticker may also be included. Several listings of the same issuer combine under that issuer. Empty holdings or any missing, zero, negative or invalid market value withhold all weighted ratios and coverage. These are supplied market values, not proof of quote or FX accuracy.

Supply one coherent reviewed annual financial profile per issuer. Financial periods must end in the selected calendar year; fiscal labels cannot override their dates. The shared company formulas recompute each eligible profile once; a saved calculated value that disagrees with its observation inputs rejects the report. Unreviewed profiles, absent issuers and unavailable metrics retain their market value in the total selected-equity denominator but do not contribute to that metric. The retrospective policy uses the supplied reviewed publication without an information cutoff. It does not independently select or establish the latest restatement. ([Observation contract](annual-financial-contract.md))

For each metric, the weighted ratio is `sum(market value × company ratio) / covered market value`. Coverage is `covered market value / all selected equity market value`, excluding cash. Different ratios can have different coverage. For example, values of 600 and 400 with margins of 40% and 10% give 28%. If the second margin is missing, the reported ratio is 40% with 60% coverage; the missing value is not zero.

The report includes gross, operating, consolidated net, common-shareholder net, CFO and FCF-after-cash-PP&E margins. Reported losses retain their sign. Insurer consolidated CFO remains included, with an explicit warning that cross-sector economic comparability is unverified. FCF uses the limited PP&E definition and remains unavailable when its inputs are missing. Company tables also show reported revenue, operating income, common earnings, CFO and cash PP&E spending in whole USD, plus available FCF, allocated CFO/FCF per basic share and reported EPS. The API also returns `weighted_company_per_share.weighted_company_eps` and `weighted_company_fcf_per_share`: covered-value-weighted averages of reported basic EPS and the source-backed allocated FCF after disclosed capital spending per basic share. Their unit is `USD_per_company_share`; they use the same coverage and exclusion rules as ratios and retain each observation or calculation in contributions. Negative or zero company values remain valid. These requested averages depend on company share units and split bases and are not portfolio-unit earnings or cash flow. Company dollar earnings are not averaged. Each weighted metric and company scalar cites its input documents beside the value. ([Company formulas](../backend/src/investor_platform/financial.py))

Every JSON result pins the input snapshot, coherent publication IDs, company calculation versions, observation IDs, source IDs, source documents, financial periods and weighting formula version. The reader-facing Markdown retains financial dates, scopes, coverage, source links and brief missing-data explanations. Internal IDs, formula versions and source hashes stay in the companion JSON. Source publication dates remain distinct from holdings dates. Synthetic input values produce an explicit **SYNTHETIC WEIGHTS — not actual portfolio exposure** label. The pilot's financial observations are real sourced company disclosures; its market values are an explicit validation fixture.

The manual library attaches prior-year values and changes for the two per-share measures. Weighted amounts use `comparison`; company rows use `per_share_comparisons` keyed by `basic_eps` and `allocated_fcf_after_disclosed_capex_per_basic_share`. Each comparison contains `prior_year`, `prior_value`, `status`, `percent_change` and `reason`. `percent_change` is the Decimal fraction `current / prior − 1`. A zero or negative prior value is `not_meaningful`; missing or incompatible inputs are `unavailable`. Prior amounts remain visible when a rate is unavailable. FY2023 has no collected FY2022 baseline.

Changes require the same common classes and split-adjustment date; year-specific source locators may differ. Weighted changes also require identical contributors and normalized equity weights. Proportional market-value scaling alone does not change weights. The caller supplies the current and prior profiles; `comparison_inputs` pins the prior report, publications, source evidence and weight snapshot. The library does not fetch new data.
